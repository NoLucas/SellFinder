# ADR-003. 인증 토큰 · IdP 전략

- **상태**: 채택 (2026-08-15)
- **제기**: C 와 D 가 각각 독립적으로 질의
- **영향 파일**: `04_api_contract.yaml`, `06_governance.md`
- **영향 에이전트**: C, D

---

## 문제

C 는 토큰에서 `tenant_id` 를 파생해야 하는데 토큰 형태가 정해지지 않았고,
D 는 콘솔 로그인 방식을 몰라 진행이 막혔다.

기업 고객은 대부분 SSO 를 요구하지만, **지금 IdP 벤더를 고르면 조기 종속**이 된다.
아직 첫 고객도 없다.

---

## 결정 — 토큰 형태는 지금 확정, IdP 선택은 미룬다

에이전트가 지금 필요한 건 **클레임 형태**뿐이다. 발급 주체는 뒤에 바꿔도 된다.

### 1. 토큰 = JWT, 클레임 형태 고정

```json
{
  "iss": "https://auth.sellfinder.kr",
  "aud": "https://api.sellfinder.kr",
  "sub": "usr_01J8XK...",
  "tenant_id": "tnt_01J8AB...",
  "role": "analyst",
  "region_scope": ["41", "11"],
  "iat": 1786000000,
  "exp": 1786003600
}
```

| 클레임 | 의미 | 비고 |
|---|---|---|
| `sub` | `user.user_id` | 서버간 토큰이면 `svc_` 접두 서비스 계정 |
| `tenant_id` | 테넌트 | **모든 격리의 근거. 요청 파라미터로 절대 받지 않는다** |
| `role` | `owner`\|`admin`\|`analyst`\|`viewer` | `01_domain_model.json` 의 rbac_matrix |
| `region_scope` | 접근 가능 지역 코드 접두사 배열 | 비었거나 없으면 전체. 예: `["41"]` = 경기도만 |
| `exp` | 만료 | 액세스 토큰 1시간, 리프레시 14일 |

`region_scope` 는 접두사 매칭이다. `"41"` 이면 `41135`(성남 분당구)가 포함된다.
영남권 담당자에게 수도권 데이터를 안 보여주는 실제 요구가 있다.

### 2. 두 가지 인증 경로

| 경로 | 방식 | 대상 |
|---|---|---|
| **서버간** | OAuth2 client credentials → JWT | 고객사 시스템이 API 직접 호출 |
| **콘솔** | 세션 → 짧은 JWT | 사람이 브라우저에서 사용 |

v1 콘솔 로그인은 **이메일 + 매직링크**로 시작한다. 비밀번호 저장을 피하면
초기 보안 표면이 크게 줄고, 나중에 SSO 로 갈아탈 때 버릴 코드도 적다.

### 3. IdP 페더레이션은 인터페이스만 남긴다

벤더를 고르지 않는다. 대신 **토큰 검증을 단일 지점으로 추상화**한다.

```
verify_token(raw) -> TokenClaims   # 이 함수 하나만 교체하면 IdP 가 바뀐다
```

- v1: 자체 발급 JWT 를 이 함수가 검증
- v1.1: 고객사 OIDC / SAML 을 붙일 때 이 함수 내부만 확장
- **애플리케이션 코드는 `TokenClaims` 만 본다.** 토큰 원문을 다른 곳에서 파싱하지 마라.

### 4. C 가 반드시 지킬 것 (`06_governance.md` §1 재확인)

- 요청의 쿼리/바디/헤더에 `tenant_id` 가 오면 **400 `TENANT_ID_NOT_ALLOWED`**.
  조용히 무시하지 마라. 무시하면 언젠가 누가 그 값을 읽는다.
- `verify_token` 이 반환한 `tenant_id` 를 DB 세션 변수에 넣어 RLS 가 강제하게 한다.
  애플리케이션 `WHERE` 절에만 의존하지 마라.
- **캐시 키에 `tenant_id` 를 포함하라.** 빠뜨리면 캐시를 통해 샌다.
- `region_scope` 필터는 예측 결과 조회·내보내기·타일 요청 **전부**에 적용한다.
  한 경로만 빠뜨려도 우회된다.

### 5. D 가 반드시 지킬 것

- 토큰을 `localStorage` 에 넣지 마라. XSS 한 번이면 전부 털린다.
  httpOnly 쿠키 또는 메모리 보관 + 리프레시.
- `role` 로 UI 를 가리는 건 **편의**일 뿐 보안이 아니다. 실제 차단은 서버가 한다.
  `viewer` 에게 버튼을 숨기되, 서버도 반드시 막혀 있어야 한다.

## 개발 중 임시 조치

인증 인프라가 서기 전까지 C 는 **개발 전용 토큰 발급 엔드포인트**를 둔다.

```
POST /v1/dev/token   { tenant_id, role, region_scope }  →  { access_token }
```

- 환경변수 `SELLFINDER_ENV=development` 일 때만 등록한다
- 운영 빌드에 이 경로가 존재하면 **S1 치명 결함**이다. 검증자가 확인 항목에 넣는다
- D 는 이걸로 테넌트 전환·권한별 UI 를 지금 테스트할 수 있다

## 미룬 것 (v1.1)

- IdP 벤더 선정 (Auth0 / Okta / Keycloak / 자체)
- SAML 지원
- SCIM 사용자 프로비저닝
- MFA

전부 `verify_token` 뒤에 숨겨지므로 지금 결정하지 않아도 된다.
