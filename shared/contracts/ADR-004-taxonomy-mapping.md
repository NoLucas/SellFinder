# ADR-004. 택소노미 1차 매핑 기준 — sbiz 우선

- **상태**: 채택 (2026-08-15)
- **제기**: A 가 `ksic_codes` / `sbiz_codes` / `card_mcc` 중 무엇을 기준으로 조인할지 질의
- **영향 파일**: `02_taxonomy.json`, `03_region_features.json`
- **영향 에이전트**: A, B

---

## 문제

`02_taxonomy.json` 의 각 노드는 세 가지 코드 체계에 매핑된다.
어느 것을 **1차 조인 키**로 삼느냐에 따라 파이프라인 구조가 달라진다.

| 체계 | 출처 | 주는 것 | 한계 |
|---|---|---|---|
| **KSIC** | 통계청 표준산업분류 | 사업체 통계, 전국 일관 | 사업체 단위라 소비액이 아님 |
| **sbiz** | 소상공인시장진흥공단 상권정보 | **점포 수, 개폐업률, 상권등급** | 소상공인 중심, 대형 유통 일부 누락, 분기 갱신 |
| **card MCC** | 카드사 가맹점 업종 | **소비 금액** | 대부분 유료·라이선스 제한 |

---

## 결정 — 1차는 `sbiz`, `ksic` 는 보조키, `card_mcc` 는 후속

### 근거

**모델이 지금 당장 계산할 수 있어야 하는 요인이 무엇인가**로 정했다.

`05_scoring_spec.md` 의 8개 요인 중 `competition`(경쟁 강도)은 **점포 수**가 원천이고,
그 점포 수를 무료로 얻을 수 있는 유일한 경로가 `sbiz` 다.
`ksic` 는 사업체 통계라 상권 단위 경쟁 밀도를 직접 주지 못한다.

즉 v1 의 무료 데이터 경로에서 **실제로 값이 나오는 건 sbiz 뿐**이다.

### 역할 배분

```
sbiz      1차 조인 키. demand_signal.store_count 의 원천.
          competition · channel_availability 요인을 채운다.

ksic      보조키. sbiz ↔ 다른 공공데이터(사업체 통계, 지자체 데이터) 조인용.
          sbiz 코드가 없는 노드의 대체 경로.

card_mcc  라이선스 확보 후 활성화. demand_signal.spend_krw 를 채운다.
          지금은 스키마에만 두고 파이프라인에 넣지 않는다.
```

### 매핑이 비어 있는 노드 처리

`02_taxonomy.json` 의 규칙대로 **상위 노드의 매핑을 상속**한다.
상속해도 없으면 그 노드는 `demand_signal` 을 만들 수 없다.

→ 예측 시 해당 노드는 `confidence.level = 'low'` 로 **강제 하향**하고,
   `05_scoring_spec.md` §4 의 강제 하향 조건("taxonomy_node 에 공개데이터 코드 매핑이 없음")에 해당시킨다.
   조용히 0 으로 채우지 마라.

---

## 이 결정의 파급 — 오히려 설계 일관성을 확인해준다

`card_mcc` 없이는 `demand_signal.spend_krw` 를 채울 수 없다.
따라서 **금액 기반 절대 추정이 불가능**하고, `spend_index` 를 점포 수와
지역 소비력 프록시로 유도해야 한다.

이는 이미 계약에 있는 규칙과 정확히 일치한다.

> **T0 테넌트에는 금액 추정을 반환하지 않는다 (null 고정)** — `05_scoring_spec.md` §2

자사 판매 데이터가 없고 카드 데이터도 없는 상태에서 금액을 내놓으면 그건 지어낸 숫자다.
랭킹은 점포 수·인구·소득만으로도 유의미하지만 절대값은 그렇지 않다.
**결정 하나가 다른 결정과 충돌하지 않는다는 건 설계가 버티고 있다는 신호다.**

`card_mcc` 라이선스를 확보하는 시점이 곧 T0 에서도 금액을 낼 수 있게 되는 시점이다.
그때 이 ADR 을 갱신한다.

---

## A 가 할 일

1. `demand_signal` 파이프라인의 조인 키를 `sbiz_codes` 로 고정
2. `02_taxonomy.json` 에서 `sbiz_codes` 가 비어 있는 노드 목록을 뽑아 보고
   → 상속으로 해결되는지, 매핑을 추가해야 하는지 판단이 필요하다
3. `data_source` 레지스트리에 상권정보 등록 시 `known_limitations` 에 명시
   - 분기 갱신으로 최대 3개월 시차
   - 무점포 사업자 미포함
   - 대형 유통 채널 일부 누락
4. `card_mcc` 기반 수집 코드는 작성하지 않는다. 라이선스 미확보 상태다
   (`06_governance.md` §3.2 — `commercial_use_allowed=false` 소스는 프로덕션 투입 금지)

## B 가 할 일

1. `spend_krw` 가 항상 null 이라는 전제로 `category_penetration` 요인을 설계
   → `store_count` 와 지역 소비력 프록시로 `spend_index` 를 유도
2. 매핑 없는 노드에 대해 `confidence` 강제 하향이 실제로 동작하는지 테스트로 강제
3. 합성 데이터 생성기도 이 제약을 반영 — `spend_krw` 를 채워두면
   실데이터로 갈 때 모델이 무너진다
